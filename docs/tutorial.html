[ SFL 0.8.0 ]安装 · 使用 · 更新

从下载安装到第一次复用，
把你的图库放在本机。

0.8.0 提供 macOS 原生 SwiftUI App，并同时提供复用本机 Node.js 22+ 的版本；Windows 与 Linux 继续使用本地网页客户端。下面按平台说明下载、首次设置、连接外部工具和升级方式。

打开 0.8.0 发布页查看完整安装限制
[ 01 ]选择安装包

按系统与运行时选择文件

系统内置 Node 版本本机 Node 版本选择建议
macOS Apple Siliconmacos-arm64.dmgmacos-arm64-no-node.dmgM 系列 Mac 选择 arm64；不想另装 Node 请选择内置 Node。
macOS Intelmacos-x64.dmgmacos-x64-no-node.dmgIntel Mac 选择 x64。两种包都是原生 SwiftUI 界面。
Windows x64windows-x64.zipwindows-x64-no-node.zip解压后运行 Start SFL.cmd；本机 Node 版要求 Node.js 22+。
Linux x64 / arm64linux-x64.zip / linux-arm64.zip文件名追加 -no-node解压后运行 start-sfl.sh；本机 Node 版要求 Node.js 22+。
macOS 提醒：0.8.0 DMG 是预览版，当前使用 ad-hoc 签名，尚未完成 Developer ID 签名与 Apple 公证。首次打开时按 macOS“隐私与安全性”的提示允许已确认来源的 App。
[ 02 ]安装与首次启动
1

下载并校验

从 v0.8.0 发布页下载对应文件和同名 .sha256。在终端运行 shasum -a 256 文件名（Windows 可用 certutil -hashfile 文件名 SHA256），确认摘要一致。

2

安装程序

macOS 将 App 拖入 Applications；Windows/Linux 解压整个目录，不要单独移动 runtime、dist 或 assets。

3

绑定两个目录

第一次启动在“设置”中指定全局 Library（长期保存已发布图形）和 Local workspace（当前工作内容）。目录由你选择，程序不会把它们推断为当前项目。

4

连接外部工具

打开“连接外部工具”，复制 Codex、Claude、Cursor 或通用 stdio MCP 配置。内置 Node 包会使用包内绝对路径；no-node 包会使用你选择的 Node 路径。

[ 03 ]日常使用

导入、审阅、发布，再复用

导入自己的图

在“创建参考图”选择图片、绘图代码和方法说明，填写数据特征、用途与许可证。SFL 只保存和管理资产，不执行 R/Python 绘图脚本。

发布不可变版本

在“我的图库”打开草稿，完成审阅记录后发布。发布版本保留来源、文件摘要和许可证，可在不同项目中检索。

搜索并确认精确预览

在“图库”搜索本机已发布内容或外部图库。先打开精确预览并确认具体版本，再复制到项目，避免只凭缩略图选择。

按需缓存外部图片

FigureYa 与 Open Figure Modules 的预览图不会随安装包全部下载。对指定图库点击“缓存图片”才会批量下载；单张预览和参考包按需获取并校验。

网络问题：默认直连 GitHub。若所在网络需要代理，在“设置”打开系统代理并填写本机回环 HTTP 代理（例如 http://127.0.0.1:7897）。不要把 198.18.x fake-ip 地址当作图库地址。
[ 04 ]更新与卸载

安全替换程序，保留你的 Library

  1. 1

    备份数据

    退出 SFL 和仍在使用旧程序的 MCP 进程，备份你指定的全局 Library 与 Local workspace。

  2. 2

    下载新版本

    从新的 GitHub Release 选择平台与架构，重新校验 SHA-256。macOS 仍需选择 arm64 或 x64，不能混用。

  3. 3

    替换程序

    macOS 用新 App 替换 Applications 中旧 App；Windows/Linux 删除或移走旧解压目录后解压新目录。不要覆盖 Library。

  4. 4

    检查连接

    启动后打开“设置”和“连接外部工具”，确认目录、Node 路径和 MCP 配置。删除程序不会自动删除用户图库。
