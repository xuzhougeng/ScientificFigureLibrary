[ 001 ] 为长期积累而设计

自己的图库，越用越有价值。

把一次作图的成果，变成有来源、可审阅、能再次使用的研究资产。

01 / LOCAL FIRST

一份图库，留在本机

自行指定全局图库目录，集中保存不同项目的图形与代码。备份这份目录，就能带走已发布的版本。

02 / REVIEW & PUBLISH

审阅之后，再放心复用

将图、代码和方法说明一起整理，记录验证情况，再发布为不可变版本。下次使用时，清楚知道自己选中了什么。

03 / PREVIEW & REUSE

选中哪张，就带走哪张

在交互式图库里预览模板，确认后将所选版本复制到项目。保留来源与版本记录，让后续修改有迹可循。

[ 002 ] 从一张图到下一次复用

把好用的方法，一起留下。

导入、审阅、发布、复用。让每张图不仅有结果，也有可以继续工作的起点。

  1. 01

    导入图与代码

    收集图形、源代码和方法说明，整理到本机图库。

  2. 02

    审阅与记录

    检查模板与文件，记录绘图验证情况及适用条件。

  3. 03

    发布固定版本

    将审阅后的内容发布为可追溯的不可变版本。

  4. 04

    在新项目中复用

    预览并确认具体模板，将所需文件复制到项目中。

图与代码保存在一起；实际绘图由宿主在你批准的 R / Python 环境中完成。

[ 003 ] 几步开始使用

接入工具，打开你的图库。

需要 Node.js 22+ 和支持 stdio MCP 的宿主。可以从发布页获取插件，也可以从源码构建。

  1. 安装插件或构建源码

    Wisp Science 可在「设置 → 插件」中安装 ZIP；其他宿主的安装方式见快速开始。

  2. 指定两个本机目录

    分别绑定全局图库与本地工作区；由你选择实际路径。

  3. 打开图库，导入第一张图

    在宿主中打开 Scientific Figure Library，导入图与代码，审阅后发布。

图和代码保存在什么地方？

保存在你指定的本机全局图库目录。已发布的版本可跨项目使用；本地工作区用于工作内容。调用远程模型或在线服务时，相关数据处理范围取决于宿主、服务与任务配置。

它会自动运行绘图脚本吗？

不会。Scientific Figure Library 负责整理、检索、预览和复制模板。实际绘图需要由宿主在你批准的 R / Python 环境中执行。

支持哪些工具？

支持 Wisp Science、Claude Science、Codex、Cursor 等宿主，也可配置为通用 stdio MCP 服务。交互式图库需要宿主支持 MCP Apps。

能使用外部模板吗？

可以。默认先检索本机已发布内容，再检索 FigureYa、Open Figure Modules 与已启用的动态个人 Provider。预览并确认具体模板后，再将所选文件带入项目。

代码与图形分别遵循什么许可？

仓库代码采用 MIT 许可证。用户导入的图形保留导入时记录的许可证；复用模板时，请核对对应来源与许可。
